# Security and production checklist

Passwords use Argon2id. Session JWTs are signed with a 32+ character random secret and expire in eight hours. Cookies are HttpOnly, SameSite=Strict, and Secure by default. Writes require a random token bound to the signed session, supplied as X-CSRF-Token. There is no browser localStorage token. Protected endpoints require an active user; writes/settings require an administrator. Login and manual checks are Redis-rate-limited and fail closed when Redis is unavailable.

Use HTTPS in production. The default HTTP Nginx configuration is for TLS-terminated deployments or development. Keep COOKIE_SECURE=true behind HTTPS. The local generator disables secure cookies solely for loopback testing; that .env must never be reused as-is on a public VPS. Configure host firewall rules, private database/Redis networks, valid TLS certificates, and trusted reverse-proxy boundaries. Nginx overwrites forwarded IP headers. Do not publish backend port 8000 directly; the deployment only publishes the reverse proxy.

JWT_SECRET, database credentials, SMTP credentials, webhook secret, reputation keys, and ENCRYPTION_KEY must be generated independently and managed outside source control. ENCRYPTION_KEY is a Fernet key and must be retained with encrypted mailbox data. Use `.env` mode 0600 or a secret manager. Environment variables are readable by VPS/container administrators. The platform's HTTPS proxy secrets are not raw IMAP/SMTP passwords: seed app passwords must be entered into the app over HTTPS or supplied through a supported secure runtime channel.

The authenticated settings API never returns mailbox passwords or integration secrets. Audit logs store actions and identifiers, not passwords/tokens/keys. Monitoring error evidence stores exception type, not exception text or credential headers. SMTP TLS and IMAP TLS validate certificates. Monitoring targets must resolve only to public addresses; MX probing pins the validated IP and retains the original hostname for certificate checks. SMTP/IMAP sender configuration is trusted operator input, so do not grant settings access to untrusted users.

Signed event ingestion authenticates raw request bytes, enforces a five-minute timestamp window, validates input, and deduplicates by unique event ID. Do not put the webhook secret in the frontend. Do not send full recipients or message bodies; recipient domains are sufficient. Configure upstream request/connection rate limits for exposure to the Internet. Nginx bounds request bodies and emits CSP, frame, referrer, and MIME headers.

There is no password recovery email flow or MFA in this release. Administrator password recovery uses the operator helper with hidden prompts. Existing JWTs persist until expiry after password changes; rotate JWT_SECRET to invalidate all sessions immediately, or mark a user inactive via an audited administrative database operation. Evaluate SSO/MFA, retention, backups, and independent security review before client production rollout. Dependency audits and tests demonstrate specific checks, not a security certification.

Back up both PostgreSQL and the encryption/configuration secrets separately, encrypted and access controlled. Never commit backups. Treat report exports as internal data. License notices are a starting inventory; review transitive dependencies and provider contracts in your distribution.

Uvicorn accepts forwarded headers from the private Compose network so per-client login rate limiting uses the Nginx-provided address. Nginx overwrites forwarding headers; the backend must remain unpublished and isolated from untrusted direct clients. If you expose or change that network boundary, restrict `--forwarded-allow-ips` to the trusted proxy addresses before doing so.
